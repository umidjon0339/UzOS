# Architecture Specific (x86)

## Educational Concepts: Memory Segmentation and the GDT

This directory contains code specific to the x86 architecture. The first fundamental concept implemented here is the **Global Descriptor Table (GDT)**.

### What is the GDT?
In x86, the GDT is used to define the characteristics of different memory areas called "segments." Even if modern OSes (like Linux or Windows) primarily rely on Paging for memory management, the x86 architecture still strictly requires a valid GDT to function.

The GDT holds an array of 8-byte entries (Segment Descriptors). Each descriptor contains:
- **Base Address**: Where the segment begins in memory.
- **Limit**: The maximum addressable size of the segment.
- **Access Byte**: Identifies the privilege level (Ring 0 for kernel, Ring 3 for user), and whether it's executable (code) or writable (data).
- **Granularity Flags**: Defines if the limit is measured in 1-byte blocks or 4KB blocks.

### The Standard Flat Setup
For our OS, we are using the "Flat Memory Model". We define:
1. **Null Descriptor**: The required empty first entry (index 0).
2. **Kernel Code Segment** (Offset 0x08): Spans from 0 to 4GB. Ring 0 privileges.
3. **Kernel Data Segment** (Offset 0x10): Spans from 0 to 4GB. Ring 0 privileges.

By overlapping code and data segments across the entire memory space (0 to 4GB), we bypass the complexities of physical segmentation, paving the way to use **Paging** as our primary memory manager in the future.

## Educational Concepts: The IDT and Interrupt Service Routines (ISRs)

The **Interrupt Descriptor Table (IDT)** is very similar to the GDT, but instead of telling the CPU about memory segments, it tells the CPU where to jump when an *Interrupt* or *Exception* occurs.

An exception is generated by the CPU when something goes wrong. For example, if a program tries to divide by zero, or access memory it shouldn't (Page Fault), the CPU immediately halts the current task and looks up the corresponding entry in the IDT.

There are 256 possible interrupt numbers:
- **0 to 31**: Reserved by Intel for CPU Exceptions.
- **32 to 255**: Available for Hardware Interrupts (like the Keyboard or Timer) and Software Interrupts (used for System Calls).

### ISRs
An **Interrupt Service Routine (ISR)** is the function that actually handles the interrupt. When an exception fires, our assembly code pushes the CPU's state (registers) onto the stack and calls our C function `isr_handler`. This allows our kernel to print a useful error message and gracefully halt (or recover) instead of triple-faulting and rebooting uncontrollably.
